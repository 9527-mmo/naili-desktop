# 奶栗桌面宠物 · 素材生产与手机审核流程

生效日期：2026-11-18。用户确认的最新工作流，优先于此前“审核后才上传任何内容”的旧规定。

## 强制流程
1. **生成**：制作新图片、动画、角色素材；统一命名 `gen1-vX.Y-动作-审核编号`。
2. **临时上传**：将**实际二进制素材**上传 GitHub `review/pending/<审核编号>/`（不是仅上传说明或生成脚本）；可由专门审核分支托管，避免污染正式发布目录。
3. **网页审核**：手机审核网页从仓库中的审核清单读取素材，直接显示原图和动画；**不要求用户重新上传图片**。展示审核编号、版本、待审状态与意见框。
4. **审核处理**：
   - **通过**：将审核通过的文件复制/移动到 `characters/naili/approved/<版本>/`，更新正式角色清单与桌面程序加载引用，移除临时审核入口。
   - **失败**：删除该审核编号下临时素材、清单和网页入口，再生成新版；**不得删除已经确认的正式素材**。
   - **待修改**：临时区保留，修改后形成新的审核编号，旧审核记录可保留为文本历史但不作为正式素材。
5. **核验**：确认 GitHub 实际文件可读取、GitHub Pages 手机上可访问，再汇报仓库路径、审核链接、提交 SHA。

## 数据与删除边界
- **失败即清理临时区**：普通 Git 删除会从最新分支移除文件，但不能保证从 Git 历史或 CDN 缓存彻底擦除。需要彻底清除历史时应另行处理。
- 已审核通过的素材和原始审核基准不能因为后续版本失败而删除。
- 手机审核操作如仅保存在浏览器本地，不能当作服务器已经收到的审核结果；需要明确回传或使用可写的审核后端。
- 生成中间文件不必上传；用户要求“生成图片后上传”的对象是**供审核的候选成品**。
- 严禁将早期占位图、重新绘制替身标注为用户已确认的 Gen 1 正式原图。
